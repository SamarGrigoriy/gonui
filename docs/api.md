# Контракт публичного API

Это обязательный контракт для реализации. Если сигнатура или семантика здесь и в коде расходятся, ошибка в коде, либо сначала нужно изменить этот документ.

Пакет: `nui`. Объём MVP — около 125 экспортируемых имён.

## 0. Общие правила

**Поток.**
- Все функции и методы вызываются **только в UI-потоке**: внутри `setup` у `Run`, в обработчиках `On*`, таймерах, `Watch` и функциях из `Do`.
- Из любого потока можно вызывать единственную функцию — `Do`. Исключение — запись в поток сообщения чата (`ChatStream.Write`, `WriteString`, `Close`, §18).
- При отладочной сборке (тег `nuidebug`) нарушение правила вызывает панику с сообщением `nui: вызов не из UI-потока — используйте nui.Do`.

**До `Run`.** До `Run` можно вызывать только `SetAppID`. Если создать виджет раньше, при отладочной сборке будет паника, а в обычной — неопределённое поведение.

**Единицы.** Все размеры задаются в **логических пикселях**. При масштабе экрана 2× кнопка шириной 100 станет 200 физических пикселей. Масштаб пересчитывает ОС (GTK) или драйвер (Win32).

**Строки.** На входе и выходе строки в UTF-8. Если в строке есть байт `\x00`, она **обрезается** на нём, потому что так устроены строки в C. Невалидные последовательности UTF-8 на входе заменяются на символ U+FFFD («�»): GTK невалидный UTF-8 не принимает. Исключение — путь в `ShowInFolder`: он передаётся как есть. Пути, которые возвращают диалоги, тоже возвращаются как есть, в кодировке файловой системы.

**Обработчики** (ADR-8):
- `On*` вызываются только в ответ на **действия пользователя**. Программные изменения их не вызывают — ни `Set*`, ни `Add`, `Clear`, `Append`;
- у события один обработчик: новый заменяет старый, `nil` снимает его;
- сигнатура — `func()`, кроме `Window.OnClose`;
- одно действие пользователя может вызвать обработчик **дважды**: вставка поверх выделения в TextView — это удаление и вставка. Обработчик читает текущее значение геттером и не считает вызовы;
- если обработчик вызывает модальный диалог, во время диалога продолжают работать таймеры, `Watch` и `Do`, потому что внутри крутится вложенный цикл событий. Это нужно учитывать: пока вы ждёте ответа `Ask`, может сработать другой обработчик.

**Уничтожение.**
- Виджеты уничтожаются вместе с окном. Кроме того, виджет уничтожается, когда его заменяют через `SetChild` или убирают из `Box` и `Grid` (`Remove`, `Clear`).
- Методы уничтоженного объекта **ничего не делают**, геттеры возвращают нулевые значения, а `Alive()` возвращает `false`.
- Если виджет создан, но никуда не вставлен, он живёт до конца программы.

**Вставка.**
- Виджет вставляется **ровно в один** контейнер. Повторная вставка — паника: `nui: виджет уже вставлен в контейнер`.
- Переносить виджет из одного контейнера в другой в MVP нельзя.

**Паники** в обработчиках завершают процесс (ADR-9).

**Различия между ОС.** Поведение одинаковое, кроме нескольких мест, где у Win32 нет нужного средства:
- `Watch` есть только на unix;
- на Windows `Progress.SetText` не отображается, а `EllipsisStart` работает как `EllipsisMiddle`.

Полный список — в [driver-win32.md](driver-win32.md), §10.

## 1. Приложение

```go
func SetAppID(id string)
```
Задаёт имя приложения до `Run`, например `"esp32-logger"`. Оно должно совпадать с именем `.desktop`-файла. На Linux это `g_set_prgname`, от него зависят `WM_CLASS` и `app_id` в Wayland, по ним панель задач находит иконку. По умолчанию берётся имя исполняемого файла.

```go
func Run(setup func()) error
var ErrNoDisplay error // "nui: нет дисплея или GTK не инициализировался"
```
- Инициализирует GTK, вызывает `setup` и крутит цикл событий до `Quit`.
- Возвращает `ErrNoDisplay`, если нет `DISPLAY`/`WAYLAND_DISPLAY` или GTK не удалось инициализировать. Тогда `setup` не вызывается.
- Вызывается один раз и только из `main` (главного потока), иначе паника.
- Цикл заканчивается в двух случаях: при вызове `Quit` или когда уничтожено окно и среди оставшихся нет ни одного видимого (ADR-15). Скрытые окна программу не держат.

```go
func Quit()
```
- Просит цикл завершиться, и `Run` возвращает `nil`.
- Если вызвать `Quit` внутри `setup`, `Run` вернётся сразу после `setup`.
- Если открыт модальный диалог, `Quit` подействует после его закрытия.

```go
func Do(fn func())
```
- Ставит `fn` в очередь на выполнение в UI-потоке. Это **единственная** функция, которую можно вызывать из любого потока или горутины.
- Всегда асинхронна: даже из UI-потока `fn` выполнится позже, а не внутри вызова.
- Порядок сохраняется: функции выполняются в том порядке, в котором вызван `Do`.
- Если `Do` вызван после завершения `Run`, функция не выполнится.
- `Do` срабатывает раньше перерисовки окна. Если вызывать его непрерывно (например, на каждый принятый байт), окно перестанет перерисовываться. Копите данные и вызывайте `Do` пачками, не чаще 20–50 раз в секунду ([runtime.md](runtime.md), §8).

```go
func Args() []string
```
- Аргументы командной строки, как `os.Args`: `Args()[0]` — программа. Можно вызывать до `Run` и из любой горутины.
- Зачем, если есть `os.Args`: в сборке TinyGo на Windows `os.Args` приходят в кодировке ANSI, и путь с русскими буквами («Открыть с помощью…» из Проводника) портится. `Args` читает `GetCommandLineW` — путь доходит целым. В сборке gc и на Linux `Args()` и `os.Args` совпадают.

## 2. Таймеры

```go
func After(ms int, fn func()) *Timer // однократно, примерно через ms миллисекунд
func Every(ms int, fn func()) *Timer // каждые ms миллисекунд, пока не вызван Stop
func (t *Timer) Stop()               // можно вызывать изнутри fn; повторный Stop ничего не делает
```
- Точность — как у цикла событий: таймер не сработает раньше срока, но может опоздать, пока занят UI-поток.
- `ms ≤ 0` означает «при первой возможности».
- После того как `After` сработал, `Stop` ничего не делает.

## 3. Ожидание файлового дескриптора (только unix)

```go
type IOCond uint8
const (
	IORead  IOCond = 1 << iota // есть что читать
	IOWrite                    // можно писать
	IOHup                      // другая сторона закрыта / устройство пропало
	IOErr                      // ошибка
)

func Watch(fd int, cond IOCond, fn func(got IOCond)) *Watcher
func (w *Watcher) Stop()
```
- `fn` вызывается в UI-потоке, когда `fd` готов. `got` — что именно произошло.
- `IOHup` и `IOErr` приходят всегда, даже если их нет в `cond` (как в `poll`).
- `Watch` не закрывает `fd` и не читает из него.
- Перед `close(fd)` **обязательно** вызовите `Stop`, иначе цикл будет крутиться на мёртвом дескрипторе.
- После `IOHup`/`IOErr` наблюдатель продолжает срабатывать, поэтому приложение должно вызвать `Stop`.
- Дескриптор лучше открывать в неблокирующем режиме (`O_NONBLOCK`), чтобы `read` в обработчике не повесил интерфейс.
- На Windows `Watch` нет. Там используется горутина с `Do`.

## 4. Общее для всех виджетов

```go
type Widget interface{ /* запечатан: реализуют только типы nui */ }

type Align uint8
const (
	AlignFill   Align = iota // занять всё доступное место (по умолчанию)
	AlignStart               // прижать к началу (влево / вверх)
	AlignCenter
	AlignEnd
)
```

Методы, которые есть у **каждого виджета** (кроме `Window`, у которого свой набор):

| Метод | Семантика |
|---|---|
| `Alive() bool` | `false` после уничтожения |
| `SetEnabled(on bool)`, `Enabled() bool` | недоступный виджет виден, но не реагирует; в контейнере недоступность распространяется на детей |
| `SetVisible(on bool)`, `Visible() bool` | скрытый виджет не занимает места в раскладке |
| `SetTooltip(text string)` | всплывающая подсказка; `""` убирает её |
| `SetContextMenu(items ...*MenuItem)` | меню по правому щелчку (и клавише «Меню», Shift+F10, когда виджет в фокусе); без аргументов — убрать. Подробнее — §5, «Контекстное меню» |
| `SetAlign(h, v Align)` | как виджет располагается в выделенной ему ячейке; по умолчанию `AlignFill, AlignFill` |
| `SetMinSize(w, h int)` | минимальный размер; `-1` — не задавать по этой оси |
| `Size() (w, h int)` | текущий размер в логических пикселях (тех же, что у `SetMinSize`) — после последней раскладки. Виджет не на экране (скрыт сам или родитель, окно не показано) — `0, 0`. Раскладка идёт в цикле событий, поэтому сразу после `Show` или изменений размер ещё прежний: спрашивайте его в обработчиках или через `After` |
| `Focus()` | передать фокус ввода |

**Цвет и фон** (ADR-19). Не у всех виджетов, а там, где это нужно для разделения зон:

| Виджет | Методы |
|---|---|
| `Window` | `SetBackground(c Color)` |
| `Box`, `Grid` | `Background(c Color)` — цепочкой, как `Spacing` и `Padding`; `SetBackground(c)` — то же без цепочки. Фон закрашивает и отступ `Padding`; подписи, флажки, ползунки и рамки внутри получают тот же фон, поля ввода остаются белыми |
| `Label` | `SetColor`, `SetBackground`, `SetBold`, `SetFontScale(f float64)` — размер шрифта относительно обычного: `1.5` — заголовок |
| `Button`, `Entry`, `TextView`, `Chat` | `SetColor(c Color)` — цвет текста, `SetBackground(c Color)` — фон |

- `Color` — `nui.RGB(r, g, b)`; `NoColor` возвращает вид темы.
- Цвета не следуют за тёмной темой ОС: задавая фон, задавайте и цвет текста.
- На Windows цветную кнопку рисует драйвер: она плоская, без визуального стиля системы.

```go
title := nui.NewLabel("Рабочее место")
title.SetFontScale(1.6)
title.SetBold(true)
title.SetColor(nui.RGB(255, 255, 255))
header := nui.HBox(title).Padding(10).Background(nui.RGB(40, 70, 120))
```

## 5. Window

```go
func NewWindow(title string, child Widget) *Window // child может быть nil
```
Окно создаётся скрытым. Значения по умолчанию:
- внутренний отступ — 12;
- размер — естественный размер содержимого;
- можно растягивать;
- окно по центру экрана (на Wayland положение выбирает композитор).

| Метод | Семантика |
|---|---|
| `SetTitle(s string)`, `Title() string` | заголовок окна |
| `SetChild(w Widget)` | заменить содержимое; старый ребёнок уничтожается |
| `Size() (w, h int)` | текущий размер окна без рамки и заголовка (вместе с отступом окна), логические пиксели. У скрытого окна — размер, с которым оно появится |
| `SetSize(w, h int)` | Если окно растягивается — его размер, пользователь может менять. Если не растягивается — фиксированный размер, но не меньше естественного размера содержимого |
| `SetResizable(on bool)` | можно ли менять размер мышью |
| `SetMaximized(on bool)` | развернуть на весь экран (с рамкой и заголовком, пользователь может восстановить); `false` — восстановить. До `Show` — окно сразу откроется развёрнутым, а `SetSize` задаст его размер после восстановления. На Linux разворачивает оконный менеджер |
| `SetFullscreen(on bool)` | полноэкранный режим: без рамки и заголовка, поверх панелей; `false` — вернуть обычный. Можно до `Show` |
| `SetPadding(px int)` | отступ между краем окна и содержимым |
| `SetBackground(c Color)` | фон окна; `NoColor` — фон темы (§4, «Цвет и фон») |
| `SetDefault(b *Button)` | кнопка по умолчанию: её нажимает Enter в `Entry` без `OnEnter` и в поле `ComboEntry` |
| `SetIconName(name string)` | иконка из темы иконок по имени, например `"utilities-terminal"` или имя из вашего `.desktop` |
| `OnClose(fn func() bool)` | пользователь закрывает окно (крестик, Alt+F4). `fn` возвращает `false` — окно остаётся. Без обработчика окно закрывается |
| `SetMenu(menus ...*Menu)` | строка меню окна; без аргументов — убрать. Подробнее — ниже, «Меню окна» |
| `SetContextMenu(items ...*MenuItem)` | меню по правому щелчку там, где у виджетов своего меню нет |
| `OnDropFiles(fn func(paths []string))` | на окно перетащили файлы или папки из файлового менеджера; `paths` — абсолютные пути, на Linux — байты имён как есть. Бросить можно на любое место окна, кроме полей ввода (туда, как и везде, перетаскивается текст). `nil` снимает обработчик |
| `OnKey(fn func(k Key, m Mod) bool)` | нажата клавиша, пока окно активно, — раньше, чем её получит виджет с фокусом. `fn` возвращает `true` — клавиша обработана, виджет её не получит. Подробнее — ниже. `nil` снимает обработчик |
| `Show()` | показать окно, а если уже показано — поднять наверх |
| `Hide()` | скрыть окно, не уничтожая его. Скрытое окно не удерживает программу: когда закроется последнее видимое окно, `Run` завершится |
| `Close()` | закрыть и уничтожить окно из кода, **без** `OnClose` |
| `Alive() bool`, `Focus()` | как у виджетов |

Когда уничтожается окно и видимых окон не остаётся, вызывается `Quit()` (ADR-15).

**Меню окна.**

```go
func NewMenu(title string, items ...*MenuItem) *Menu // меню в строке меню
func Item(text string, fn func()) *MenuItem          // пункт
func CheckItem(text string, fn func(on bool)) *MenuItem // пункт с флажком
func SubMenu(title string, items ...*MenuItem) *MenuItem // вложенное меню
func Sep() *MenuItem                                 // разделитель
func (i *MenuItem) Shortcut(k Key, m Mod) *MenuItem  // сочетание клавиш (цепочкой)
func (i *MenuItem) SetEnabled(on bool); Enabled() bool
func (i *MenuItem) SetChecked(on bool); Checked() bool // CheckItem
func (i *MenuItem) SetText(s string)

w.SetMenu(
	nui.NewMenu("Файл",
		nui.Item("Открыть…", open).Shortcut('O', nui.ModCtrl),
		nui.Item("Сохранить", save).Shortcut('S', nui.ModCtrl),
		nui.SubMenu("Недавние", nui.Item("отчёт.txt", openReport)),
		nui.Sep(),
		nui.Item("Выход", nui.Quit).Shortcut('Q', nui.ModCtrl)),
	nui.NewMenu("Вид",
		nui.CheckItem("Боковая панель", func(on bool) { panel.SetVisible(on) })),
)
```

| Что | Семантика |
|---|---|
| Сочетание | показывается в меню справа от текста и выбирает пункт, пока окно активно, — раньше `OnKey` и виджета с фокусом. Буквы — по положению клавиши, как в `OnKey`: Ctrl+O работает и в русской раскладке. У выключенного пункта сочетание не срабатывает и уходит дальше. На Windows подпись английская («Ctrl+O»), как у самой Windows; на Linux — как в теме GTK |
| `CheckItem` | выбор переключает флажок и вызывает `fn` с новым состоянием. `SetChecked` флажок ставит без вызова (ADR-8) |
| `SetEnabled(false)` | пункт серый, не выбирается ни мышью, ни сочетанием. У `SubMenu` — всё подменю |
| Состояние | `SetEnabled`, `SetChecked`, `SetText` можно вызывать и до `SetMenu`, и после |
| `SetMenu` повторно | прежняя строка уничтожается вместе с пунктами (их методы ничего не делают). Меню и пункт попадают в окно один раз; повтор — паника |
| Размер окна | `SetSize` и `Size` — область под строкой меню: строка меню добавляется к окну, а не отнимается у содержимого, на всех ОС одинаково |
| Клавиатура | F10 (на Windows и Alt) открывает меню — как в любой программе ОС. Мнемоник (подчёркнутых букв) nui не задаёт: `&` в тексте показывается как есть |

**Контекстное меню.**

```go
func (w *widget) SetContextMenu(items ...*MenuItem) // у любого виджета
func (w *Window) SetContextMenu(items ...*MenuItem) // у окна: где у виджетов меню нет
func (c *Chat) SetContextMenu(items ...*MenuItem)   // у ленты сообщений

chat.SetContextMenu(
	nui.Item("Скопировать ответ", func() { nui.SetClipboard(chat.LastMessage()) }),
	nui.Sep(),
	nui.Item("Очистить", chat.Clear),
)
```

| Что | Семантика |
|---|---|
| Когда открывается | правый щелчок; клавиша «Меню» или Shift+F10, когда виджет в фокусе |
| Чьё меню | виджета под указателем; если у него своего нет — ближайшего контейнера выше (`Box`, `Grid`, `Split`, страница `Tabs`…), затем окна. `Box` с меню покрывает свои подписи и пустое место |
| Поля ввода | у `Entry` и `TextView` с меню nui оно заменяет их обычное («Вырезать, Копировать, Вставить»); без меню nui поле показывает своё |
| `List` | правый щелчок сначала выбирает строку под указателем (`OnSelect`), как в файловых менеджерах; в пункте меню её номер — `Selected()` |
| Пункты | те же `Item`, `CheckItem`, `SubMenu`, `Sep`; меню и пункт — в одном месте один раз. Сочетания клавиш в контекстном меню только подписываются: срабатывают сочетания строки меню окна |
| Повторный `SetContextMenu` | прежнее меню уничтожается вместе с пунктами |

**Клавиши окна.**

```go
type Key uint32 // 'A'…'Z', '0'…'9', ' ' или константа
const (
	KeyEnter, KeyEscape, KeyTab, KeyBackspace, KeyDelete, KeyInsert,
	KeyHome, KeyEnd, KeyPageUp, KeyPageDown, KeyLeft, KeyRight, KeyUp, KeyDown,
	KeySpace, KeyF1 // F2…F12 — KeyF1+1…KeyF1+11
)
type Mod uint8 // биты
const ModShift, ModCtrl, ModAlt

w.OnKey(func(k nui.Key, m nui.Mod) bool {
	switch {
	case k == 'S' && m == nui.ModCtrl:
		save()
	case k == nui.KeyEscape:
		w.Close()
	default:
		return false // клавиша — виджету с фокусом
	}
	return true
})
```

- Буквы и цифры — по положению клавиши, независимо от раскладки и Shift: в русской раскладке Ctrl+S — это `'S'` с `ModCtrl`, Shift+1 — `'1'` с `ModShift`. Цифры цифрового блока — те же `'0'`…`'9'`, его Enter — `KeyEnter`.
- О знаках препинания, мультимедийных клавишах, самих Shift, Ctrl и Alt и об отпускании клавиш nui не сообщает. Повтор при удержании клавиши приходит как новое нажатие.
- Обработанный Enter не нажимает кнопку по умолчанию и не вызывает `OnEnter` поля; обработанная буква не попадает в поле. Ввод текста (`OnChange`) этим путём не отслеживают: он идёт и через метод ввода и вставку.

## 14. Разделитель, рамка, прокрутка

```go
func NewSeparator() *Separator               // горизонтальная линия (для VBox)
func NewVSeparator() *Separator              // вертикальная линия (для HBox)
func NewFrame(title string, child Widget) *Frame // рамка с заголовком; методы SetTitle, SetChild
func NewScroll(child Widget) *Scroll         // полосы прокрутки, если child не помещается
```

**Прокрутка.** Box растёт вместе с содержимым: каждая добавленная кнопка увеличивает его минимальный размер, и окно растягивается, чтобы всё поместилось. Чтобы длинный ряд прокручивался, положите его в `Scroll`, а `Scroll` — с `Expand` (или задайте ему `SetMinSize`):

```go
list := nui.VBox()
w := nui.NewWindow("Кнопки", nui.VBox(nui.NewLabel("Кнопки:"), nui.Expand(nui.NewScroll(list))))
w.SetSize(300, 400)
w.Show()
for i := 1; i <= 100; i++ {
	list.Add(nui.NewButton("Кнопка "+strconv.Itoa(i), nil)) // окно не растёт — ряд прокручивается
}
```

- Минимальный размер `Scroll` мал (полосы прокрутки), поэтому окно не растёт, когда содержимое увеличивается. Естественный размер — по содержимому: окно без `SetSize` при первом показе будет высотой во весь ряд (но не больше экрана). Задайте окну `SetSize` или прокрутке `SetMinSize`.
- Дети прокрутки растягиваются по ширине, как в обычном `VBox`; горизонтальная полоса появляется, только если содержимое не помещается и в минимальную ширину.
- На GTK полосы прокрутки оверлейные: появляются при наведении и прокрутке колесом. На Windows видны всегда, когда нужны.
- Для длинных однородных списков (тысячи строк) удобнее и быстрее `List` (§20): он создаёт только видимые строки.

## 15. Раскладка

Подробная семантика — в [layout.md](layout.md). Методы, которые возвращают тот же объект, можно вызывать цепочкой. Это сделано сознательно: так удобно описывать дерево интерфейса.

```go
func VBox(items ...Widget) *Box // сверху вниз
func HBox(items ...Widget) *Box // слева направо
func (b *Box) Add(items ...Widget) *Box
func (b *Box) Remove(items ...Widget) *Box // убрать и уничтожить
func (b *Box) Clear() *Box                 // убрать и уничтожить всех детей
func (b *Box) Spacing(px int) *Box  // расстояние между детьми, по умолчанию 6
func (b *Box) Padding(px int) *Box  // отступ вокруг, по умолчанию 0

func Expand(w Widget) Widget // пометить: w забирает свободное место по главной оси Box
func Stretch() Widget        // пустая растягивающаяся вставка
```
- `Expand` вызывается **до** вставки, например `VBox(a, Expand(list), b)`. Если вызвать его у уже вставленного виджета, будет паника.
- Если в Box нет ни одного `Expand` и ни одного `Stretch`, свободное место остаётся в конце.
- `Remove` и `Clear` уничтожают виджеты, как `SetChild` уничтожает прежнего ребёнка: методы удалённого виджета ничего не делают, `Alive()` — `false`, вставить его снова нельзя. Соседи занимают освободившееся место. Спрятать на время, не уничтожая, — `SetVisible(false)`. `Remove` виджета не из этого контейнера — паника; уже уничтоженного — ничего.

Список, который пересобирается целиком (результаты поиска, карточки):

```go
results.Clear()
for _, r := range found {
	results.Add(nui.NewLabel(r.Title))
}
```

```go
func NewGrid() *Grid
func (g *Grid) Add(col, row int, w Widget) *Grid
func (g *Grid) AddSpan(col, row, cols, rows int, w Widget) *Grid
func (g *Grid) Remove(items ...Widget) *Grid  // убрать и уничтожить; ячейка освобождается
func (g *Grid) Clear() *Grid                  // всех детей; ExpandCol и ExpandRow остаются
func (g *Grid) ExpandCol(col int) *Grid       // колонка забирает свободное место по ширине
func (g *Grid) ExpandRow(row int) *Grid       // строка — по высоте
func (g *Grid) Spacing(colGap, rowGap int) *Grid // по умолчанию 6, 6
func (g *Grid) Padding(px int) *Grid
```
Если две ячейки пересекаются, при отладочной сборке будет паника, а в обычной — неопределённое наложение.

```go
func HSplit(first, second Widget) *Split // панели слева и справа, граница вертикальная
func VSplit(first, second Widget) *Split // сверху и снизу
func (s *Split) SetPosition(px int) *Split // размер первой панели
func (s *Split) Position() int
```
- Границу между панелями пользователь двигает мышью: боковое меню и чат, список и просмотр.
- Первая панель держит свой размер, когда окно растягивается, — растёт вторая. Без `SetPosition` первая панель получает свой естественный размер.
- Сжать панель меньше её минимального размера нельзя ни мышью, ни `SetPosition`: `SetPosition(10)` у панели с минимумом 96 даст 96. Минимум задают сами виджеты и `SetMinSize`.
- Скрытая панель (`SetVisible(false)`) отдаёт всё место другой, границы нет.
- Граница: в GTK — линия в 1 точку с широкой невидимой полосой захвата, на Windows — полоса в 5 точек с курсором «↔», как у Проводника.
- Запомнить положение: `Position()` в `OnClose` окна, восстановить — `SetPosition` при запуске.

```go
split := nui.HSplit(menu, chat).SetPosition(220)
```

```go
func NewTabs() *Tabs
func (t *Tabs) Add(title string, page Widget) *Tabs // страница с ярлыком title — в конец
func (t *Tabs) Remove(pages ...Widget) *Tabs        // убрать и уничтожить вместе с ярлыками
func (t *Tabs) Len() int
func (t *Tabs) Page(i int) Widget                   // вне диапазона — nil
func (t *Tabs) Current() int                        // текущая страница; без страниц — -1
func (t *Tabs) SetCurrent(i int)
func (t *Tabs) Title(i int) string
func (t *Tabs) SetTitle(i int, title string)
func (t *Tabs) OnChange(fn func())                  // пользователь выбрал другую вкладку
```
- Вкладки — несколько страниц на одном месте; сверху ярлыки, видна страница выбранного. Страница — любой виджет, обычно `VBox` или `Grid`.
- Первая добавленная страница становится текущей. Размер вкладок — по самой большой странице, поэтому окно не прыгает при переключении. Не меньше самого широкого ярлыка: остальные ярлыки, если не помещаются, прокручиваются стрелками.
- `OnChange` — только выбор пользователя: щелчок по ярлыку, стрелки на ярлыках, Ctrl+PgUp и Ctrl+PgDn, когда фокус во вкладках (на Windows также Ctrl+Tab и Ctrl+Shift+Tab). `SetCurrent`, `Add`, `Remove` его не вызывают (ADR-8). Новый номер — `Current()`.
- Удалили или спрятали (`SetVisible(false)`) текущую страницу — текущей становится следующая, а если её нет — предыдущая. У спрятанной страницы спрятан и ярлык; выбрать её `SetCurrent` нельзя.
- `Remove` уничтожает страницы, как `Box.Remove`; номера следующих сдвигаются. Закрыть текущую вкладку: `tabs.Remove(tabs.Page(tabs.Current()))`.
- Пока страница не текущая, её `Size()` — `0, 0`.
- `&` в заголовке — обычный символ, как у кнопок.

```go
tabs := nui.NewTabs().
	Add("Общие", general).
	Add("Сеть", network)
tabs.OnChange(func() { status.SetText(tabs.Title(tabs.Current())) })
```

Типичная форма «подпись: поле»:

```go
nui.NewGrid().
	Add(0, 0, nui.NewLabel("Порт:")).    Add(1, 0, port).
	Add(0, 1, nui.NewLabel("Скорость:")).Add(1, 1, baud).
	ExpandCol(1)
```

## 16. Диалоги

Все диалоги **модальные и синхронные**: функция возвращается, когда диалог закрыт. Пока он открыт, внутри крутится вложенный цикл событий (см. §0). `parent` может быть `nil`.

```go
func Message(parent *Window, title, text string)   // информация, кнопка OK
func Alert(parent *Window, title, text string)     // ошибка или предупреждение, кнопка OK
func Ask(parent *Window, title, text string) bool  // Да/Нет; true — «Да»; Esc — false
```
`title` — крупный заголовок сообщения, `text` — пояснение под ним, может содержать `\n`.

```go
type Filter struct {
	Name     string   // "Логи"
	Patterns []string // {"*.log", "*.txt"}
}

func OpenFile(parent *Window, title string, filters ...Filter) (path string, ok bool)
func OpenFiles(parent *Window, title string, filters ...Filter) (paths []string, ok bool)
func SaveFile(parent *Window, title, name string, filters ...Filter) (path string, ok bool)
func ChooseFolder(parent *Window, title string) (path string, ok bool)
```
- `ok == false`, если пользователь отменил выбор.
- `OpenFiles` — один или несколько файлов одного каталога (Ctrl или Shift + щелчок). При `ok == true` срез не пуст; порядок — как отдал диалог ОС.
- `SaveFile` сам спрашивает подтверждение, если файл уже существует; `name` — предлагаемое имя.
- На Linux используется системный диалог, в песочнице — через портал.

## 17. Оболочка и буфер обмена

```go
func OpenURI(uri string) bool      // открыть "https://…" или "file:///…" программой по умолчанию
func ShowInFolder(path string) bool // открыть файловый менеджер с выделенным файлом
```
- `ShowInFolder` просит файловый менеджер выделить файл (D-Bus `org.freedesktop.FileManager1` на Linux, `explorer /select` на Windows). Запрос асинхронный: функция не ждёт файловый менеджер, и интерфейс не замирает. Если файловый менеджер ответил ошибкой (например, такой службы нет), nui сам открывает папку.
- `true` — запрос отправлен или папка открыта. `false` — не удалось ни то, ни другое (например, нет D-Bus-сессии и нет программы для `file://`).
- `path` — абсолютный путь в файловой системе (не URI).

```go
func SetClipboard(text string) // положить текст в буфер обмена (Ctrl+V в любой программе)
func Clipboard() string        // текст из буфера; "" — пусто или там не текст
```
- Только текст. Переводы строк в nui — `\n`; на Windows в буфере они `\r\n`, nui переводит в обе стороны.
- `Clipboard` синхронный: на Linux он ждёт ответа программы, которая владеет буфером, и всё это время крутит вложенный цикл событий (как модальный диалог, §16). Обычно ответ приходит за миллисекунды.
- На Linux (X11 и Wayland) текст в буфере хранит сама программа. После её выхода он остаётся, только если в системе есть менеджер буфера обмена (в GNOME, KDE и Xfce он есть): nui разрешает GTK передать ему текст. На Windows текст хранит система.

Кнопка «Скопировать ответ» для чата (§18):

```go
copyBtn := nui.NewButton("Скопировать ответ", func() { nui.SetClipboard(chat.LastMessage()) })
```

## 18. Chat — готовый чат

Верхнеуровневый виджет для переписки, например с ИИ. Лента сообщений (TextView только для чтения, с переносом и прокруткой в конец), многострочное поле ввода (Enter отправляет, Shift+Enter переводит строку), кнопки «Отправить» и «Стоп». Собран из родных виджетов, поэтому выглядит как своя ОС и работает везде, где работают они. Если программа чат не использует, он не попадает в бинарник.

```go
func NewChat() *Chat                          // Widget: вставляется как любой виджет
func (c *Chat) OnSend(fn func(text string))   // Enter или «Отправить», непустой текст (может быть многострочным)
func (c *Chat) Add(who, text string)          // готовое сообщение
func (c *Chat) Stream(who string) *ChatStream // сообщение, которое приходит частями
func (c *Chat) OnStop(fn func())              // «Стоп» во время ответа
func (c *Chat) OnReply(fn func(m ChatMessage)) // ответ (Stream) закончен и весь в ленте
func (c *Chat) SetBusy(on bool); Busy() bool
func (c *Chat) Clear(); Text() string
func (c *Chat) LastMessage() string            // текст последнего сообщения без подписи
func (c *Chat) Messages() []ChatMessage        // история: все сообщения по порядку
func (c *Chat) LoadJSON(data []byte) error     // очистить ленту и показать историю из JSON
func (c *Chat) JSON() []byte                   // история в JSON — для файла

type ChatMessage struct{ Who, Text string }    // подпись ("" — без неё) и текст
func (c *Chat) SetPlaceholder(s string)
func (c *Chat) SetLabels(you, send, stop string) // по умолчанию «Вы», «Отправить», «Стоп»
func (c *Chat) Focus()

func (s *ChatStream) Write(p []byte) (int, error)     // io.Writer — из любой горутины
func (s *ChatStream) WriteString(str string) (int, error)
func (s *ChatStream) Close() error                     // из любой горутины
var ErrChatClosed error
```

| Что | Семантика |
|---|---|
| Лента | сообщение — строка «who:», текст и пустая строка; `who == ""` — без подписи. Текст можно выделить и скопировать |
| `OnSend(fn)` | к вызову `fn` поле уже очищено, а сообщение пользователя («Вы:») уже в ленте. Текст из одних пробелов не отправляется. Пока чат занят, отправить нельзя, но вводить можно |
| `Stream(who)` | пишет «who:» и делает чат занятым: «Отправить» недоступна, «Стоп» видна (если задан `OnStop`). Текст копится в буфере потока, а в ленту его переносит таймер UI-потока примерно 25 раз в секунду — частые мелкие куски не перегружают цикл событий. Символ UTF-8, разрезанный между двумя `Write`, не ломается |
| `Close()` | ответ закончен: остаток уходит в ленту, чат перестаёт быть занятым. Повторный `Close` ничего не делает; запись после него — `ErrChatClosed` |
| `OnReply(fn)` | сообщение, начатое `Stream`, закончено — `Close`, «Стоп» или новое сообщение поверх, — и весь его текст уже в ленте и в истории (`Messages`, `JSON`). Один вызов на сообщение, в UI-потоке; при «Стоп» — раньше `OnStop`, при новом сообщении — до него. Здесь сохраняют историю; `Close` вызывается из горутины, а `OnReply` — уже в UI-потоке, `Do` не нужен |
| `OnStop(fn)` | «Стоп» сначала заканчивает текущий ответ (дальше `Write` вернёт `ErrChatClosed`, и `io.Copy` остановится сам), потом вызывает `fn` — в нём отменяют запрос (`context.CancelFunc`) |
| `Add`, `Stream`, `Clear` посреди ответа | текущий ответ сначала заканчивается: в ленте сообщения не перемешиваются |
| `LastMessage()` | текст последнего сообщения (`Add`, `Stream` или отправленного пользователем) без «who:». У незаконченного `Stream` — то, что уже в ленте; после `Clear` — `""`. Для «Скопировать ответ»: `nui.SetClipboard(chat.LastMessage())` (§17) |
| Уничтожение | вместе с окном, как любой виджет; поток уничтоженного чата молча отбрасывает текст |

**Потоки.** `ChatStream.Write`, `WriteString` и `Close` — **исключение** из правила §0: их можно вызывать из любой горутины. Все остальные методы `Chat` — только в UI-потоке.

Чат с ИИ — ответ приходит частями по сети:

```go
chat := nui.NewChat()
var cancel context.CancelFunc
chat.OnSend(func(q string) {
	var ctx context.Context
	ctx, cancel = context.WithCancel(context.Background())
	st := chat.Stream("ИИ")
	go func() {
		defer st.Close()
		if err := askModel(ctx, q, st); err != nil { // askModel пишет текст ответа в io.Writer
			fmt.Fprintf(st, "\n[ошибка: %v]", err)
		}
	}()
})
chat.OnStop(func() { cancel() })
w := nui.NewWindow("Чат", chat)
w.SetSize(460, 420)
w.Show()
```

**История в JSON.** `LoadJSON` очищает ленту и показывает сообщения по порядку, как `Add`. При ошибке лента не меняется, ошибка начинается с `nui: JSON чата:` и называет байт или номер сообщения. Понимает два вида:

```json
[
  {"who": "Вы", "text": "Как прочитать файл целиком?"},
  {"who": "ИИ", "text": "data, err := os.ReadFile(\"заметки.txt\")"}
]
```

```json
{"messages": [
  {"role": "system", "content": "Ты помощник по Go."},
  {"role": "user", "content": "Как прочитать файл целиком?"},
  {"role": "assistant", "content": "os.ReadFile"}
]}
```

| Поле | Как читается |
|---|---|
| подпись | `"who"`, иначе `"name"`. Без них — по `"role"`: `user` — подпись пользователя (`SetLabels`, по умолчанию «Вы»), `assistant` — «ИИ»; `system`, `developer`, `tool`, `function` в ленте не показываются; другая роль — подписью как есть |
| текст | `"text"`, иначе `"content"`: строка или массив частей `[{"type": "text", "text": "…"}]` — части склеиваются, картинки пропускаются. Сообщение без текста (например, `"content": null` с вызовом инструментов) пропускается |
| прочее | неизвестные поля и поля верхнего уровня (`"model"` и т. п.) не мешают |

`JSON()` пишет первый вид — по сообщению в строке. Сохранить и загрузить историю:

```go
save := func() { os.WriteFile("история.json", chat.JSON(), 0o644) }
chat.OnSend(func(q string) { save(); /* … запрос к модели … */ }) // вопрос уже в истории
chat.OnReply(func(nui.ChatMessage) { save() })                   // ответ дописан целиком

if data, err := os.ReadFile("история.json"); err == nil {
	if err := chat.LoadJSON(data); err != nil {
		nui.Alert(w, "История не загружена", err.Error())
	}
}
```

`Messages()` — та же история срезом: её удобно отправлять модели как контекст разговора. Сообщение, которое ещё приходит (`Stream`), в ней — с тем текстом, что уже в ленте.

JSON разбирает сама nui (`internal/core`, без `encoding/json`): программа с чатом не растёт на размер `encoding/json`.

Сеть, разбор потокового ответа модели и ключи — дело приложения: nui не тянет `net/http` в бинарник. Полный пример без сети, с эхо-ботом, — [examples/chat](../examples/chat/main.go).

## 19. Image — картинка

```go
func NewImage() *Image                        // пустая, 0×0
func (i *Image) SetData(data []byte) error    // байты файла: PNG, JPEG, GIF, BMP
func (i *Image) SetFile(path string) error
func (i *Image) SetFit(width, height int)     // вписать с сохранением пропорций; 0 — без ограничения
func (i *Image) Clear()
func (i *Image) ImageSize() (width, height int) // размер в файле, после поворота по EXIF
var ErrImage error
```

| Что | Семантика |
|---|---|
| Форматы | PNG (с прозрачностью), JPEG, GIF (первый кадр), BMP — на всех ОС. Декодирует ОС: GdkPixbuf на Linux, GDI+ на Windows. Свой декодер в бинарник не попадает, программы без `Image` не растут |
| Размер | в логических пикселях: картинка 100×100 при масштабе экрана 200 % занимает 200×200 точек. Картинка рисуется из исходных точек под масштаб экрана, поэтому крупный файл остаётся чётким. Без `SetFit` — размер файла |
| `SetFit(w, h)` | большая картинка уменьшается, чтобы влезть в `w×h`, пропорции сохраняются; маленькая не увеличивается. Действует и на картинки, заданные позже. `(0, 0)` — исходный размер |
| Место | минимальный и естественный размер — размер картинки. Если места больше (`Expand`, `AlignFill`), картинка стоит по центру, лишнее место — фон панели |
| EXIF | JPEG с тегом поворота (снимки с телефона) показывается повёрнутым, как в просмотрщиках; `ImageSize` — уже повёрнутый размер |
| Ошибки | `SetData` с данными, которые не картинка, — `ErrImage`; `SetFile` — ошибка чтения или `ErrImage`. Прежняя картинка остаётся |
| Память | хранятся байты файла (из них картинка перерисовывается при смене масштаба) и картинка в размере показа; полноразмерная декодированная копия не хранится |

Картинка, выбранная пользователем:

```go
img := nui.NewImage()
img.SetFit(480, 360)
open := nui.NewButton("Открыть картинку…", func() {
	path, ok := nui.OpenFile(w, "Картинка", nui.Filter{Name: "Картинки", Patterns: []string{"*.png", "*.jpg", "*.jpeg", "*.gif", "*.bmp"}})
	if ok {
		if err := img.SetFile(path); err != nil {
			nui.Alert(w, "Не удалось открыть картинку", err.Error())
		}
	}
})
```

Картинка, вшитая в программу: `//go:embed logo.png` и `img.SetData(logo)`.

Не умеет: анимацию GIF, SVG (на Linux может сработать, если в системе есть загрузчик librsvg, но это не гарантируется), растягивание под размер окна — размер задаёт `SetFit`.

## 20. List — список и таблица

```go
func NewList(columns ...string) *List                         // заголовки; без них — простой список
func (l *List) SetRows(n int, cell func(row, col int) string) // данные по требованию
func (l *List) Update()                                        // текст строк поменялся
func (l *List) Rows() int
func (l *List) Selected() int                                  // -1 — ничего
func (l *List) Select(row int)                                 // -1 — снять
func (l *List) OnSelect(fn func())
func (l *List) OnActivate(fn func(row int))                    // двойной щелчок или Enter
```

| Что | Семантика |
|---|---|
| Данные | строки не хранятся: `cell(row, col)` вызывается в UI-потоке, когда строка видна. Список на миллион строк открывается сразу. `cell` должна быть быстрой и не менять данные |
| `SetRows` | новые данные: выделение снимается, прокрутка — в начало, `OnSelect` не вызывается. Данные поменялись, а число строк то же, — `Update`: видимые строки перерисуются |
| Колонки | ширина — по заголовку и первым 100 строкам (не больше 400 пикселей), пользователь меняет её мышью; последняя колонка забирает свободное место. Длинный текст — с многоточием. Заголовки видны, если хоть один не пуст |
| Выбор | одна строка. `OnSelect` — пользователь выбрал другую строку или снял выбор; `Select` и `SetRows` его не вызывают (ADR-8). Список с фокусом сам строку не выбирает |
| `OnActivate` | двойной щелчок по строке или Enter на ней; `row` — эта строка. Enter в списке не нажимает кнопку по умолчанию |
| Размер | как у `TextView`: свои полосы прокрутки, минимальный размер мал (46×71) — задайте `Expand` или `SetMinSize` |

Список файлов:

```go
files, _ := os.ReadDir(dir)
l := nui.NewList("Имя", "Размер")
l.SetRows(len(files), func(row, col int) string {
	if col == 0 {
		return files[row].Name()
	}
	info, _ := files[row].Info()
	return strconv.FormatInt(info.Size(), 10)
})
l.OnActivate(func(row int) { nui.OpenURI("file://" + filepath.Join(dir, files[row].Name())) })
```

Нет пока: сортировки по щелчку на заголовке, выбора нескольких строк, значков и флажков в строках, редактирования ячеек.

## 21. Canvas — рисование

```go
func NewCanvas(draw func(p *Painter)) *Canvas // draw рисует холст; может быть nil
func (c *Canvas) Redraw()                      // нарисовать заново
func (c *Canvas) OnMouse(fn func(e MouseEvent))

func (p *Painter) Size() (w, h float64)
func (p *Painter) SetColor(c Color)            // NoColor — цвет текста темы
func (p *Painter) SetLineWidth(w float64)
func (p *Painter) Line(x1, y1, x2, y2 float64)
func (p *Painter) Rect(x, y, w, h float64); FillRect(x, y, w, h float64)
func (p *Painter) Ellipse(x, y, w, h float64); FillEllipse(x, y, w, h float64)
func (p *Painter) Text(x, y float64, s string) // (x, y) — левый верхний угол
func (p *Painter) TextSize(s string) (w, h float64)

type MouseEvent struct {
	Kind           MouseKind // MouseDown, MouseUp, MouseMove, MouseWheel
	X, Y           float64   // от левого верхнего угла холста
	Button         int       // 1 — левая, 2 — средняя, 3 — правая
	Mod            Mod
	WheelX, WheelY float64   // −1 — влево/вверх, +1 — вправо/вниз, на щелчок колеса
}
```

| Что | Семантика |
|---|---|
| Когда рисует | `draw` вызывается, когда холст надо показать: первый показ, изменение размера, перекрытие другим окном, `Redraw`. Несколько `Redraw` подряд — одна перерисовка. `Painter` действует только внутри `draw`: сохранённый на потом ничего не рисует |
| Координаты | логические пиксели от левого верхнего угла, как у `SetMinSize`; на экране с масштабом 150 % холст 200×100 — 300×150 точек, рисунок масштабируется сам. Сглаживание включено. Чёткая линия толщиной 1 — по координате с половиной (`10.5`): целая координата — граница между точками, линия ляжет на две |
| Начальное состояние | цвет — цвет текста темы, толщина линии — 1, фон — фон окна или цветной панели. Свой фон — `FillRect(0, 0, w, h)` первым делом |
| Текст | шрифтом интерфейса; `\n` — перевод строки. Размер — `TextSize`: чтобы выровнять или вписать |
| Размер холста | своего нет (0×0): `SetMinSize` или `Expand` |
| Мышь | нажатие, отпускание, движение над холстом, колесо. Пока кнопка нажата, движение и отпускание приходят и за пределами холста (координаты могут быть отрицательными или больше размера). На Windows координаты — целые (точки экрана, пересчитанные в логические пиксели), на GTK бывают дробными. `OnMouse` получает и движение настоящего указателя, если он над холстом |

График с маркером, который ходит за мышью:

```go
mx := 0.0
var c *nui.Canvas
c = nui.NewCanvas(func(p *nui.Painter) {
	w, h := p.Size()
	p.SetColor(nui.RGB(255, 255, 255))
	p.FillRect(0, 0, w, h)
	p.SetColor(nui.RGB(40, 90, 200))
	p.SetLineWidth(2)
	for i := 1; i <= 100; i++ {
		x0, x1 := w*float64(i-1)/100, w*float64(i)/100
		p.Line(x0, h/2-math.Sin(x0/w*2*math.Pi)*h/2, x1, h/2-math.Sin(x1/w*2*math.Pi)*h/2)
	}
	p.FillEllipse(mx-5, h/2-math.Sin(mx/w*2*math.Pi)*h/2-5, 10, 10)
})
c.OnMouse(func(e nui.MouseEvent) {
	if e.Kind == nui.MouseMove {
		mx = e.X
		c.Redraw()
	}
})
c.SetMinSize(400, 200)
```

Нет пока: многоугольников и кривых (только отрезки), картинок на холсте, своего шрифта текста, полупрозрачных цветов, двойного щелчка и клавиатуры у холста (клавиши — `Window.OnKey`).

## 23. Пример целиком

```go
package main

import "nui"

func main() {
	nui.SetAppID("nui-demo")
	err := nui.Run(func() {
		status := nui.NewLabel("")
		status.SetBold(true)
		name := nui.NewEntry()
		name.SetPlaceholder("Имя")
		agree := nui.NewCheck("Согласен")
		var w *nui.Window
		ok := nui.NewButton("Отправить", func() {
			if !agree.Checked() {
				nui.Alert(w, "Нужно согласие", "Поставьте галочку «Согласен».")
				return
			}
			status.SetColor(nui.RGB(0, 120, 40))
			status.SetText("Привет, " + name.Text())
		})
		w = nui.NewWindow("Форма", nui.VBox(name, agree, status, nui.Stretch(), ok))
		w.SetSize(360, 200)
		w.SetDefault(ok)
		w.OnClose(func() bool { return nui.Ask(w, "Выход", "Закрыть программу?") })
		w.Show()

		n := 0
		nui.Every(1000, func() { n++; w.SetTitle("Форма · " + itoa(n) + " с") })
	})
	if err != nil {
		println(err.Error())
	}
}

func itoa(n int) string { // в приложении можно и strconv.Itoa
	if n == 0 {
		return "0"
	}
	var b [20]byte
	i := len(b)
	for ; n > 0; n /= 10 {
		i--
		b[i] = byte('0' + n%10)
	}
	return string(b[i:])
}
```
