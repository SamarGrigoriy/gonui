# Цели, метрики и нецели

## Исходные требования

1. **Простота**: и API, и внутреннее устройство.
2. **Минимальный размер** бинарника.
3. **Никаких тяжёлых зависимостей**: ни во время сборки, ни во время работы.
4. **Нативность**: настоящие виджеты ОС и машинный код, без браузера и виртуальной машины.
5. **Кроссплатформенность**, по возможности. Главная платформа — Linux (Debian), вторая — Windows, macOS необязательна.

## Измеримые цели

Цифры с пометкой «оценка» — предварительные: их замеряют в спайках S1/S2 ([roadmap.md](roadmap.md)) и после этого фиксируют в `size-budget.txt`.

| Метрика | Цель | Как проверяется |
|---|---|---|
| Размер `examples/hello`, TinyGo | ≤ 64 КБ | `make size` |
| Размер `examples/logger`, TinyGo | **≤ 250 КБ** | `make size` |
| Размер `examples/hello`, gc | замер S1 + 10 % (оценка: 1,3–1,8 МБ) | `make size` |
| Размер `examples/logger`, gc | размер hello (gc) + 300 КБ | `make size` |
| Внешние Go-модули | 0 (в `go.mod` нет `require`) | ревью `go.mod` |
| Стандартные пакеты в ядре | только белый список ([size.md](size.md)) | `make deps` |
| Зависимости для запуска (Linux) | только `libgtk-3-0` ≥ 3.22 (её зависимости ставятся вместе с ней) | `ldd` |
| Зависимости для сборки | Go ≥ 1.22, gcc; для малой сборки — TinyGo | [build.md](build.md) |
| Время сборки hello, gc, повторная | ≤ 3 с | `time make dev` |
| Время сборки hello, TinyGo | ≤ 20 с | `time make small` |
| Время от запуска до окна | ≤ 200 мс; почти всё уходит на инициализацию GTK, на долю nui — ≤ 5 мс (оценка) | `strace -r` / ручной замер |
| Память | её определяет GTK (оценка: 20–40 МБ RSS); на долю nui — ≤ 1 МБ | `/proc/<pid>/status` |
| Объём публичного API в MVP | ≤ 130 экспортируемых имён | `go doc -all nui` |
| Hello world | ≤ 15 строк | `examples/hello` |

### Поддерживаемые системы

| ОС | Минимум | Основная цель |
|---|---|---|
| Debian | 12 (bookworm), GTK 3.24 | 12 и 13, amd64 и arm64 |
| Ubuntu / Mint / прочие | GTK ≥ 3.22, glibc ≥ 2.34 (Ubuntu 22.04 и новее) | не тестируются в CI, но должны работать |
| Windows (фаза 5) | 10 версии 1703 и новее (нужен Per-Monitor DPI v2) | 10, 11, x64 |
| macOS (фаза 6, необязательно) | — | — |

GTK ≥ 3.22 нужен потому, что используются `gtk_show_uri_on_window` (3.22), `GtkFileChooserNative` (3.20), `gtk_label_set_xalign` и `gtk_text_view_set_monospace` (3.16).

glibc ≥ 2.34 нужна потому, что релизные бинарники собираются на Debian 12, а бинарник, собранный с glibc 2.34 и новее, ссылается на `__libc_start_main@GLIBC_2.34`. Точную границу для каждого релиза показывает `make abi` ([driver-gtk3.md](driver-gtk3.md), §9).

## Эталон: «Запись логов ESP32» (Win32, C)

Ориентир по размеру — программа `esp32_logger.exe` из соседнего проекта. Это один файл на C, только Win32 API, сборка `gcc -Os -s`.

| Часть | Размер |
|---|---|
| Весь exe | 223 КБ |
| из них вшитые драйверы USB-переходников (CAB, LZX) | ≈ 175 КБ |
| из них иконка, манифест, ключ | несколько КБ |
| **код и данные программы** (окно, 12 контролов, логика, шифрование через CNG) | **≈ 40 КБ** |

Что из этого следует:

- **Обычный Go (gc) до 250 КБ не дотянет.** Его рантайм (сборщик мусора, планировщик, метаданные типов, таблица pclntab) весит около 1 МБ даже в hello world после `-s -w`. Флагами это не лечится. UPX сжимает примерно до трети, но у него свои минусы ([size.md](size.md)).
- **TinyGo даёт hello world размером в десятки КБ.** На нём 250 КБ на всё приложение — реальная цель. Препятствие и пути обхода описаны в [decisions.md](decisions.md), ADR-4. Спайк S3 его снял: окно, кнопка, модальный диалог, таймеры и `Watch` на выпущенном TinyGo — 35 952 байта (ADR-17).
- Поэтому код библиотеки обязан собираться **обоими тулчейнами**, а правила размера соблюдаются с первого коммита.
- **250 КБ — бюджет приложения, а не гарантия nui.** На долю nui приходится около 30–50 КБ ([size.md](size.md), §2), остальное — код и импорты приложения. Логгер укладывается, потому что обходится без `fmt` и `time` ([acceptance.md](acceptance.md), §5). Приложение, которое их импортирует, в 250 КБ может не уложиться даже с TinyGo.

Приёмочное приложение [acceptance.md](acceptance.md) — Linux-версия того же интерфейса. Значит, сравнение будет честным: та же функциональность, та же цель по размеру.

## Почему не существующие библиотеки

Размеры hello world — порядок величин, на разных версиях отличаются.

| | Как рисует | Hello world | Чего требует | Нативный вид на Linux | Главная проблема для нас |
|---|---|---|---|---|---|
| Fyne | OpenGL, свои виджеты | ~20–30 МБ | cgo, GL, `-dev`-пакеты | нет | размер, «чужой» вид |
| Wails | системный webview | ~8–10 МБ | cgo, WebKitGTK (сотни МБ в системе) | нет (HTML) | WebKit, двойной стек (Go + JS) |
| Gio | GPU, immediate mode | ~8–10 МБ | cgo, `-dev`-пакеты Wayland и X11 | нет | размер, свой ввод текста и IME |
| andlabs/ui (libui) | нативные виджеты | ~5 МБ | cgo, статическая libui | да (GTK3) | заброшен, cgo с заголовками |
| gotk4 | GTK4 | десятки МБ, сборка идёт минутами | cgo, `libgtk-4-dev` | да | только Linux, огромные биндинги |

Ближе всего к нашей идее libui. nui повторяет её модель (тонкий слой над нативными виджетами), но:

- **без cgo-заголовков**, поэтому собирается TinyGo;
- **с контрактом размера**: белый список импортов и контроль размера в CI;
- **с ядром, ориентированным на Go**: `Do` для горутин, `Watch` для файловых дескрипторов, без собственных потоков.

## Нецели

Чего nui **не делает**. Если такое захочется, это повод для отдельного ADR, а не для «маленького исключения».

- Собственная отрисовка виджетов, темы, стили, CSS. Внешний вид даёт ОС. Исключение — небольшой набор оформления (ADR-19): цвет текста и фон у подписей, кнопок, полей и чата, фон у Box, Grid и окна, жирность и размер шрифта подписей. Этого хватает, чтобы разделить зоны интерфейса; тем, наследования стилей и CSS по-прежнему нет.
- Анимации и переходы.
- HTML, webview, rich text.
- Data binding, реактивность, декларативный DSL, генерация кода.
- Мобильные платформы, браузер (wasm).
- Пиксельная одинаковость на всех ОС. Цель — одинаковое **поведение** раскладки, а не одинаковые пиксели.
- Многооконные документы (MDI), докинг панелей, плагины.
- Собственный менеджер HiDPI, IME и доступности. Всё это делает ОС.
- Обёртки для всего GTK. В nui входят только функции, которые нужны API ([driver-gtk3.md](driver-gtk3.md)).
