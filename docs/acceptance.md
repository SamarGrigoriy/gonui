# Приёмочное приложение: «Запись логов ESP32» для Linux

`examples/logger` — Linux-версия интерфейса эталонной программы `esp32_logger.exe` (Win32, C, 223 КБ, из которых код — около 40 КБ; [goals.md](goals.md)). Она решает две задачи:

1. **Проверить API в деле.** Всё приложение пишется **только** через [api.md](api.md). Если чего-то не хватает, это дыра в API: её закрывают в api.md, а не обходят в приложении.
2. **Честно сравнить размер.** Та же функциональность — цель TinyGo ≤ 250 КБ.

## 1. Что переносится, а что нет

| Функция оригинала | В Linux-версии |
|---|---|
| Выбор порта, автоопределение переходника, обновление при подключении | да (§4) |
| Скорость из списка или своя, по умолчанию 9600 | да |
| Галочка «Время компьютера в начале каждой строки» | да |
| Запись с потерей не больше последней секунды при сбое | да (`fsync` раз в секунду; сбой — отключение питания или падение ядра, см. §7) |
| Порт пропал → жду → снова на связи, запись в тот же файл | да |
| Цветная строка состояния, счётчики, путь к файлу | да |
| Подтверждение закрытия во время записи | да |
| «Открыть папку» с выделенным файлом | да (`ShowInFolder`) |
| Установка драйверов CP210x и CH340 | **не нужна**: драйверы `cp210x` и `ch341` есть в ядре Linux |
| Шифрование RSA + AES-GCM | **вне рамок**: пишется обычный `.log`. В TinyGo `crypto/rsa` тянет `math/big` и не влезает в бюджет. Если понадобится — libcrypto через тот же приём с прототипами, отдельной задачей |
| Запрет сна во время записи | вне рамок (на Linux нужен D-Bus `login1.Inhibit`; это расширение для фазы 6) |

## 2. Интерфейс

Окно «Запись логов ESP32», нерастягиваемое, около 400×240.

```
┌ Запись логов ESP32 ──────────────────────────────┐
│ Порт:      [ttyUSB0 — CP2102 (Silicon Labs)   ▾] │
│ Скорость:  [9600        ▾]  бод                   │
│            [✓] Время компьютера в начале каждой строки │
│ [ ●  Начать запись          ] [ Открыть папку ]   │
│                                                   │
│ ●  Идёт запись: ttyUSB0, 9600 бод   (жирный, цвет)│
│ Записано 12,4 КБ · 00:01:37                       │
│ /home/user/esp32_logs/esp32_ttyUSB0_2026-…log (серый, …) │
└───────────────────────────────────────────────────┘
```

Код раскладки (весь интерфейс — около 20 строк):

```go
port := nui.NewCombo()
baud := nui.NewComboEntry("9600", "19200", "38400", "57600", "74880",
	"115200", "230400", "460800", "921600")
baud.SetSelected(0)
stamps := nui.NewCheck("Время компьютера в начале каждой строки")
stamps.SetChecked(true)
start := nui.NewButton("●  Начать запись", onStart)
folder := nui.NewButton("Открыть папку", onFolder)
state := nui.NewLabel("");  state.SetBold(true); state.SetEllipsis(nui.EllipsisEnd)
info := nui.NewLabel("");   info.SetEllipsis(nui.EllipsisEnd)
file := nui.NewLabel("");   file.SetEllipsis(nui.EllipsisMiddle); file.SetColor(nui.RGB(128, 128, 128))

form := nui.NewGrid().
	Add(0, 0, nui.NewLabel("Порт:")).     AddSpan(1, 0, 2, 1, port).
	Add(0, 1, nui.NewLabel("Скорость:")). Add(1, 1, baud).Add(2, 1, nui.NewLabel("бод")).
	AddSpan(1, 2, 2, 1, stamps).
	ExpandCol(2)

w := nui.NewWindow("Запись логов ESP32", nui.VBox(
	form,
	nui.HBox(nui.Expand(start), folder),
	state, info, file,
))
w.SetResizable(false)
w.SetSize(400, 240)
w.SetDefault(start)
w.SetIconName("esp32-logger")
w.OnClose(onClose)
w.Show()
```

## 3. Состояния и тексты

Тексты взяты из оригинала (`update_ui` в `esp32_logger.c`), «COM-порт» заменён на «порт».

| Состояние | Строка состояния (цвет) | Строка информации | Кнопка |
|---|---|---|---|
| Порт найден, не пишем | «Готово к записи» (цвет темы) | «Лог сохранится в папку ~/esp32_logs» | «●  Начать запись» |
| Порт не найден | «Порт не найден» (цвет темы) | «Подключите аппарат USB-кабелем — порт появится сам» | «●  Начать запись» (недоступна) |
| Идёт запись | «●  Идёт запись: ttyUSB0, 115200 бод» (красный `RGB(200,0,0)`) | «Записано 12,4 КБ · 00:01:37»; если за 5 с нет данных — «00:00:05 · данных пока нет — аппарат включён?» | «■  Остановить запись» |
| Порт пропал во время записи | «Порт ttyUSB0 пропал — жду подключения» (оранжевый `RGB(200,100,0)`) | «Записано … · …» | «■  Остановить запись» |
| Запись остановлена | «Запись сохранена» (зелёный `RGB(0,120,40)`) | «12,4 КБ · 00:01:37» | «●  Начать запись» |

Пока идёт запись:
- заголовок окна — «● Запись логов ESP32»;
- выбор порта, скорость и галочка недоступны;
- третья строка показывает полный путь к файлу (серым, с многоточием в середине).

## 4. Поведение

**Список портов.**
1. Источник — `/dev/serial/by-id/*`: это символьные ссылки со стабильными именами вида `usb-Silicon_Labs_CP2102_…-if00-port0` → `../../ttyUSB0`.
2. Подпись элемента — «ttyUSB0 — CP2102 (Silicon Labs)». Она разбирается из имени by-id; если разобрать не удалось, подписью служит само имя.
3. Если каталога by-id нет, используются `/dev/ttyUSB*` и `/dev/ttyACM*`.
4. Обновление: `nui.Every(1000)` сравнивает новый список со старым. Combo перестраивается, только если список изменился и запись **не** идёт. Выбор пользователя сохраняется по by-id-пути.

**Скорость.** `baud.Text()` → целое число от 1 до 4 000 000, иначе `Alert`. Скорость 74880 (на ней загрузчик ESP32 печатает boot-лог) нестандартная: она задаётся через `termios2` с `BOTHER`. Драйвер может молча подставить ближайшую скорость, которую умеет переходник, и не вернуть `EINVAL`. Например, старый CP2102 (без «N») вместо 74880 ставит 76800 — это 2,6 % расхождения. Поэтому `ser_open` после `TCSETS2` перечитывает скорость и возвращает фактическую. Если она отличается от запрошенной больше чем на 1 %, строка состояния показывает фактическую: «●  Идёт запись: ttyUSB0, 76800 бод (запрошено 74880)».

**Начало записи:**
1. `fd = ser_open(путь, скорость, &факт)` — C-хелпер приложения (§5):
   - `open(O_RDONLY | O_NOCTTY | O_NONBLOCK | O_CLOEXEC)`;
   - `ioctl(TIOCEXCL)` — монопольный доступ;
   - `TCGETS2` → сырой режим, `BOTHER`, скорость, без `HUPCL` → `TCSETS2` → снова `TCGETS2`: какую скорость драйвер поставил на самом деле.

   **DTR и RTS.** Аппарат не должен перезагружаться при старте записи (как в оригинале). Ядро Linux поднимает DTR и RTS при каждом `open()`, и termios не позволяет этого избежать. Плату спасает схема автосброса ESP32: при одновременно поднятых DTR и RTS она сброс не делает, а драйверы `cp210x` и `ch341` поднимают обе линии одним запросом к переходнику. Это проверяется на реальной плате (§7).

   Снимать линии через `TIOCMBIC` после `open` бесполезно: если импульс сброса и был, он прошёл в момент `open`. Если какая-то плата всё же сбрасывается, это фиксируется в отчёте как ограничение платформы.
2. Ошибки → `Alert` с текстом:

   | errno | Текст |
   |---|---|
   | `EACCES` | «Нет доступа к /dev/ttyUSB0. Добавьте пользователя в группу dialout: `sudo usermod -aG dialout $USER`, затем выйдите из системы и войдите снова.» |
   | `EBUSY` (от `TIOCEXCL`) | «Порт ttyUSB0 занят другой программой. Закройте монитор порта (PlatformIO, Arduino IDE, screen, minicom).» Для `ttyACM*` добавить: «…или ModemManager.» |
   | `ENOENT`, `ENODEV` | «Порт ttyUSB0 не найден. Переподключите USB-кабель.» |
   | `EINVAL` (от `TCSETS2`) | «Порт ttyUSB0 не поддерживает скорость N бод.» |
3. Файл: `~/esp32_logs/esp32_<tty>_<ГГГГ-ММ-ДД_чч-мм-сс>.log`. Каталог создаётся, если его нет. Если писать нельзя — `Alert`.
4. `watch = nui.Watch(fd, nui.IORead, onData)`, `tick = nui.Every(1000, onTick)`.

**Приём данных** (`onData`):
- читать порциями по 4 КБ до `EAGAIN`;
- если галочка включена, вставлять «`[чч:мм:сс.ммм] `» в начало каждой строки. Признак «в начале строки» хранится между вызовами, так что разрыв строки между порциями обрабатывается правильно;
- сразу писать в файл, без буфера в памяти (как в оригинале);
- прибавлять счётчик байт.

**`onTick`, раз в секунду:**
- `fsync` файла, если были новые данные. При сбое теряется не больше последней секунды;
- обновить строки состояния;
- в режиме «порт пропал» — попытка переоткрыть порт по тому же by-id-пути.

**Порт пропал** (`onData` получил `IOHup`/`IOErr`, или `read` вернул 0 / `EIO`):
1. `watch.Stop()`, затем `close(fd)`;
2. в файл пишется строка «`--- порт пропал чч:мм:сс ---`»;
3. состояние «жду подключения».

Когда порт открывается снова: строка «`--- порт снова на связи чч:мм:сс ---`», новый `Watch`, запись продолжается в тот же файл.

**Остановка:** `watch.Stop()`, `close(fd)`, `fsync`, закрыть файл, `tick.Stop()`, состояние «Запись сохранена».

**«Открыть папку»:**
- был лог → `nui.ShowInFolder(путь)`;
- иначе → `nui.OpenURI("file://" + каталог)`.

**Закрытие окна** (`onClose`):
- если идёт запись → `nui.Ask(w, "Идёт запись", "Остановить её и закрыть программу?\n\nВсё, что уже принято, сохранено в файл.")`;
- «Да» → остановка, вернуть `true`; «Нет» → `false`.

## 5. Как уложиться в 250 КБ

Приложению разрешено всё, но бюджет общий ([size.md](size.md)). Поэтому:

| Задача | Чем | Чем не стоит |
|---|---|---|
| Время для меток и имени файла | C-хелпер `ts_now(char out[16])` и `file_stamp(char out[20])`: `clock_gettime(CLOCK_REALTIME)` + `localtime_r` | `time.Now().Format`: форматирование и часовые пояса тянут много кода |
| Длительность записи | C-хелпер `mono_ms()`: `CLOCK_MONOTONIC` | `time` |
| Числа и размеры («12,4 КБ», «00:01:37») | свои функции `fmtSize`, `fmtDur`, `itoa` (по 10–15 строк) | `fmt`, `strconv` |
| Порт | `examples/logger/serial_linux.c`: `ser_open`, `ser_read` (возвращает `-errno`), `ser_close` | `golang.org/x/sys/unix`: внешний модуль и вопрос совместимости с TinyGo |
| Файлы, каталоги, by-id | `os` (`OpenFile`, `Write`, `Sync`, `MkdirAll`, `ReadDir`, `Readlink`) — **замерить** в фазе 4. Если `os` в TinyGo окажется слишком тяжёлым, перейти на C-хелперы `open`/`write`/`fsync`/`opendir`/`readlink` | — |

`serial_linux.c` подключает системные заголовки libc (`<fcntl.h>`, `<unistd.h>`, `<sys/ioctl.h>`, `<asm/termbits.h>` без `<termios.h>` — иначе конфликт определений, `<time.h>`). Они из `libc6-dev` и `linux-libc-dev`, которые входят в `build-essential`. Это не `-dev`-пакеты GTK, так что принцип ADR-3 не нарушается.

Если TinyGo с `-libc=glibc` системных заголовков не видит (проверяется в S2), объявления пишутся вручную. Значения одинаковы для x86_64 и aarch64:
- `TCGETS2 = 0x802C542A`, `TCSETS2 = 0x402C542B`, `TIOCEXCL = 0x540C`;
- `BOTHER = 0010000`, `CBAUD = 0010017` (восьмеричные);
- `O_NOCTTY = 0400`, `O_NONBLOCK = 04000`, `O_CLOEXEC = 02000000` (восьмеричные);
- `struct termios2 { unsigned c_iflag, c_oflag, c_cflag, c_lflag; unsigned char c_line, c_cc[19]; unsigned c_ispeed, c_ospeed; }`.

Приложение не использует горутин, поэтому собирается с `-scheduler=none`: это самый маленький вариант.

## 6. Selftest логгера (тег `selftest`)

1. C-хелпер создаёт псевдотерминал (`posix_openpt`, `grantpt`, `unlockpt`, `ptsname`). Подчинённая сторона играет роль порта.
2. Запись стартует на `ptsname`, скорость 115200, без меток времени.
3. Через `After(100)` в ведущую сторону пишется `"hello\r\nмир\r\n"`.
4. Через `After(300)` ведущая сторона закрывается, пока запись ещё идёт: логгер переходит в «жду подключения», а в файл пишется строка «порт пропал».
5. Через `After(600)` запись останавливается, лог-файл читается и сравнивается побайтно с `"hello\r\nмир\r\n"` и строкой «`--- порт пропал чч:мм:сс ---`» (время при сравнении маскируется).
6. Выход: код 0 — успех, 1 — расхождение (`os.Exit` разрешён только в selftest-сборке).

## 7. Чек-лист приёмки (DoD фазы 4)

**На реальном оборудовании.** Платы ESP32 с CP2102 и с CH340, Debian 12 и Debian 13.

- [ ] Порт появляется в списке через 1–2 с после подключения и исчезает после отключения (когда запись не идёт).
- [ ] Запись на 115200: лог совпадает с выводом `cat /dev/ttyUSB0` в те же секунды.
- [ ] Скорость 74880: после сброса платы кнопкой EN в логе читаемый boot-лог ROM. На CP2102 без «N» строка состояния показывает фактическую скорость 76800; читается ли лог при таком расхождении — записать в отчёт.
- [ ] Начало записи **не перезагружает** работающую плату (по логу: нет строки `rst:` в момент старта).
- [ ] Выдернули кабель: оранжевый статус и строка «порт пропал» в файле. Вставили: «снова на связи», запись идёт в тот же файл.
- [ ] Порт открыт в `screen` → понятное сообщение «занят».
- [ ] Пользователь не в группе `dialout` → сообщение с командой `usermod`.
- [ ] `kill -9` во время записи: в файле есть всё, что пришло до этого момента (данные пишутся в файл сразу, без буфера в памяти).
- [ ] Жёсткий сброс машины во время записи (виртуальная машина — reset в гипервизоре; железо — `echo b | sudo tee /proc/sysrq-trigger`): после загрузки в файле есть всё, кроме последней секунды. Именно это проверяет `fsync`. `kill -9` его не проверяет: после `write()` данные лежат в кэше ядра и переживают смерть процесса.
- [ ] Галочка времени: метки стоят в начале **каждой** строки, включая строки на стыке порций.
- [ ] Закрытие окна во время записи спрашивает подтверждение; «Нет» оставляет окно и продолжает запись.
- [ ] «Открыть папку» выделяет файл в Nautilus (GNOME) и Dolphin (KDE).
- [ ] Работает на Wayland и на X11; интерфейс не обрезается при `GDK_SCALE=2`.

**Размер и зависимости:**
- [ ] TinyGo: `stat -c %s bin/small/logger` ≤ 256 000 (или бюджет gc, если релизный тулчейн — gc).
- [ ] `readelf -d`: в `NEEDED` только стек GTK и libc.
- [ ] Отчёт `docs/reports/size-logger.md`:
  - разбивка `tinygo build -size full`;
  - сравнение с `esp32_logger.exe`: 223 КБ всего, около 40 КБ без драйверов;
  - что заняло больше всего места и что можно ужать.
